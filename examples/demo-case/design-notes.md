# 设计说明：告警抑制器（演练用虚构材料）

> 这份文档和 `src/` 里的代码都是为了演练专利技能虚构的，不对应任何真实系统、真实客户或真实数据。

## 一、要解决的问题

一次机房网络抖动，8 分钟内推了 1173 条告警，值班群刷屏，真正要处理的根因只有 4 类。
值班的人翻不完，直接把群设成免打扰，结果半小时后一条真正的 P0 也被漏看了。

## 二、现有做法为什么不够

| 做法 | 问题 |
|---|---|
| 固定静默期（同一条告警 5 分钟内只发一次） | 一刀切。P0 也要等 5 分钟，P2 又压不住 |
| 按告警名精确去重 | 告警标题里带实例名、时间戳和数值，"磁盘 91.2%" 和 "磁盘 93.8%" 被当成两条 |
| 按时间桶聚合（每分钟汇总一次） | 所有告警都被拖延一个桶，严重告警的首条延迟不可接受 |
| 人工配置抑制规则 | 规则要人写、要维护，新告警类型总是漏配 |

## 三、我们的做法

四个机制串起来，前一个的输出改变后一个的行为：

**1. 归一化指纹**
把告警标题里易变的部分抹成通配符再取哈希：UUID、`YYYY-MM-DD HH:MM:SS` 形式的时间戳、
所有数字。抹完再折叠空白、转小写，和告警来源拼在一起取 SHA-256 前 16 位。
"node-a 磁盘使用率 91.2% 超过阈值" 和 "node-a 磁盘使用率 93.8% 超过阈值" 得到同一个指纹。

**2. 抑制窗口**
每个指纹一个独立窗口。窗口外的第一条立即发出并开窗；窗口内的同指纹告警只计数，不发。

**3. 自适应窗口长度**
窗口长度 = 该等级的基础窗口 × 退避倍数 ^ 连续吵闹次数，并设上限。
基础窗口按等级分：P0 30 秒、P1 120 秒、P2 600 秒；退避倍数 2；上限 3600 秒。
一个窗口内压过条数大于 0，下一个窗口的连续吵闹次数加 1；一个窗口内没有重复，减 1（不小于 0）。

数字算例：一条 P1 告警连续吵，窗口依次是 120 秒 → 240 秒 → 480 秒 → 960 秒 → 1920 秒 → 3600 秒（封顶）。
中间只要安静一个窗口，下一个窗口就回落到 960 秒这一档，而不是直接回到 120 秒。

**4. 升级逃逸与窗口摘要**
窗口内如果来了一条同指纹但等级更高的告警（P2 → P0），立即放行，把当前窗口提前结算，
按新等级重开一个窗口，连续吵闹次数归零。
窗口正常关闭时，如果压过的条数大于 0，补发一条摘要，写明这一窗合并了多少条。

## 四、跑出来的数

拿那次 1173 条的原始告警流重放：

| 指标 | 原始 | 过抑制器后 |
|---|---|---|
| 推送条数 | 1173 | 47（其中 12 条是窗口摘要） |
| 不同根因类别 | 4 | 4（都发出来了） |
| P0 首条延迟 | 0 秒 | 0 秒 |
| 被压掉的条数 | — | 1138 |

## 五、已知的边界和还没解决的

- 指纹把数字全抹掉，所以 "CPU 90%" 和 "CPU 20%" 会落到同一个指纹。目前靠等级升级逃逸兜底，
  等级相同但数值跨了档的情况压得住但看不见，这是取舍不是 bug。
- 时钟回拨没处理：`ts` 变小的告警会被当成窗口内重复。
- 遗忘时间用的是"关闭后再过一个上限窗口"，这个值没调过。
- 多实例部署时窗口状态在进程内存里，没有共享。

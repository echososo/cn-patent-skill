# 五分钟演练：一个故意写坏的申请文件

这一整个文件夹都是虚构的——虚构的系统、虚构的代码、虚构的申请文件。
目的只有一个：你手头还没有自己的材料，也能立刻看到这套技能能干什么。

## 四句台词，复制就能用

打开你的 agent（Claude Code / Codex / Cursor / WorkBuddy / nanobot 都行），把这个技能装好之后，
在装有本技能的目录下依次说：

```
专利审查：examples/demo-case/bad-draft.md
```
用平衡的模拟实质审查视角看这份稿子。它会按客体、新颖性、创造性、充分公开、支持、清楚逐项过，
每个问题给"位置—问题—最小修改"，最后给一张权项覆盖表。默认只报告，不改你的文件。

```
专利驳回：examples/demo-case/bad-draft.md
```
换成驳回视角再打一遍，专找最难答复、法律上又站得住的攻击路径，并且每条攻击都要先写出
申请人的最强反驳，再判断反驳能不能推翻它。

```
专利撰写：examples/demo-case/
```
把 `src/` 里的代码、测试和 `design-notes.md` 当作发明人交来的材料，从头写一件新申请：
先吃透代码、定发明点、做检索，再出权利要求和说明书。

```
专利交底书：examples/demo-case/
```
同一份材料，换成写给代理人看的技术交底书：固定七章，方案往细里写，末尾附一节「证据状态」——
每条机制标清是材料里本来就有的，还是技能替发明人补写的。附图走 mermaid 出 PNG
（要出图得先装浏览器和 playwright，见 `INSTALL.md` 第五节；出不了图不影响成文，围栏原样留着）。

想让它审完直接动手改，就把"修改"说出来：`专利审查并修改：examples/demo-case/bad-draft.md`。
话里没有"修改"两个字，审查类任务只报告问题，不动文件。

## 先跑一遍形式检查（不用模型，几秒钟）

```
python3 scripts/check_patent_package.py examples/demo-case/bad-draft.md
```

这是纯规则的表面检查，不判断新颖性和创造性，只抓确定性的毛病。
这份坏稿子应该抓出 3 个 ERROR、7 个 WARN。

输出最后会多一行 `FAIL: errors=3 warnings=7 files=1`，退出码是 1——**这不是脚本坏了**，
是包里所有脚本共用的机读约定：稿子有问题就以非零退出码结束，好让 agent 和 CI 直接判读。
这份稿子本来就是故意写坏的，抓出问题才对。（约定见 `SKILL.md` 的「脚本判读约定」一节。）

## 这个文件夹里有什么

```
demo-case/
├── README.md                    本文件
├── design-notes.md              虚构的设计文档（发明人视角的材料）
├── bad-draft.md                 故意写坏的申请文件
├── src/
│   ├── alert_suppressor.py      虚构实现，约 134 行
│   └── test_alert_suppressor.py 13 个用例，python3 -m unittest 能跑
├── 审查输出-样例/               手工放的矩阵和审查问题（虚构），演示固定表格格式
└── 图谱/                        用上面材料生成的案件图谱（可重新生成，见下）
```

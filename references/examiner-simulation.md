# 模拟审查

用于完整初稿形成后、终审前、核心权利要求重大修改后，或现有技术组合风险较高时。局部措辞修改不机械执行。模拟必须基于当前唯一母版和可核验证据，不虚构对比文件，不把内部模拟冒充官方审查意见。

## 常规调用语路由

- 用户说 `专利审查`：只运行平衡模拟实质审查；
- 用户说 `专利驳回`：只运行对抗式驳回压力测试；即使此前没有运行平衡审查也直接执行，但标明这一限制；
- 用户说 `专利审查和专利驳回`：依次运行平衡审查、驳回压力测试和必要的平衡回归；
- 上述调用默认只审查。用户明确说 `并修改` 或 `后修改` 时，才处理已核实的问题并生成一个新版本，不覆盖母版。

用户无需说出两份内部提示词的正式名称。调用语与用户更完整、明确的本次指令冲突时，以完整指令为准。这里的 `专利驳回` 指对当前申请稿进行内部驳回视角分析；如果用户提供真实审查意见通知书或驳回决定并要求答复，则转入“专利审查意见答复”，不得误当成内部压力测试。

## 两个独立审查视角

本技能保留两份独立提示词，不把它们合并成同一轮自问自答：

1. [平衡模拟实质审查](prompts/balanced-substantive-examination.md)：用于完整初稿的第一轮系统审查，既找授权障碍，也识别可维持的支点；
2. [对抗式驳回压力测试](prompts/adversarial-rejection-stress-test.md)：用于第一轮问题已经修正之后，从最不利但有法律和证据基础的角度寻找残余攻击路径。

渐进式读取规则：进入完整初稿审查时先读并运行第一份；只有完成相应修改、进入终审、创造性风险较高或答复稿需要反向测试时，再读第二份。普通局部修改、只核对一个批注或材料尚未形成完整申请文件时，不加载两份长提示词。

| 所处阶段 | 调用内容 | 目的 |
|---|---|---|
| 完整初稿刚形成 | 先运行平衡模拟实质审查 | 校准客体、支持、公开和现有技术风险，确认可维持的发明支点 |
| 第一轮重要问题已修正、准备终审 | 在修订稿上运行驳回压力测试 | 找最强残余驳回路径，验证退守梯度是否真的能守住 |
| 独立权利要求或核心实施例重大修改 | 对受影响部分重跑平衡审查；必要时再跑红队 | 防止修改超范围、效果链断裂或引入新的组合攻击 |
| 真实审查意见答复稿形成 | 先用红队攻击答复和拟修改权项，再做平衡回归 | 检查审查员可能继续追击之处，同时防止过度缩窄 |
| 仅改措辞、格式或单个批注 | 不调用两份长提示词 | 维持任务范围，避免无关扩审 |

## 标准运行顺序

完整新案或“可提交终审”默认执行：

1. 在当前初稿上独立运行平衡模拟实质审查；
2. 核实其中引用的法源、对比文件和申请文件位置，只处理有证据支持的问题；
3. 修正致命和重要问题，更新权项—支持矩阵、创造性矩阵和退守梯度；
4. 在修订后的新母版上单独运行对抗式驳回压力测试；
5. 对红队理由逐项验证，修正能够维持的理由，不为未证实猜想缩窄权项；
6. 对受影响的权项和说明书段落再运行一次平衡回归，检查修改基础、保护范围代价和新引入的一致性问题。

如果用户只要求普通初稿评审而不允许改稿，只运行平衡审查；如果用户明确要求终审、完整压力测试或同时使用两个视角，则在同一母版上分开运行两轮并合并结论，但不修改文件。若材料不足以做检索增强审查，先完成文件内审并输出待检索项，不把不确定性包装成驳回结论。需要现场补检索时，入口按 [检索与材料规范](search-and-materials.md) 的「检索入口」一节执行；入口不可达只能降到 `文件内审模式`，不得据此写“未发现现有技术”。

## 版本绑定、独立性与问题台账

- 每轮开始记录唯一母版路径、文件名、修改时间和 SHA-256；多文件审查包分别记录指纹。审查结论只对该精确版本有效，实质修改后原结论自动失效，至少重跑受影响检查并重新核对全文一致性。
- 可提交终审或高风险案件，在运行环境支持真正独立上下文时，平衡审查与驳回压力测试分别使用新上下文；后一视角接收完整当前审查包，但不接收前一视角的结论。这样得到的是两次独立证据判断，不是两个模型投票。
- 无法建立独立上下文时仍可顺序运行，但必须标明 `同一上下文复核，独立性受限`，不得声称已经获得两个独立审查员放行。
- 建立稳定问题编号，**前缀只能从下表取，这是封闭集，不得自造**。台账要跨轮沿用编号，前缀一旦自造，
  下一轮就对不上，读者也会按字面误读缺陷性质（实测踩过：把「权 1 混进实现细节」编成 `OBJ-01`，
  同一份报告却写着「客体未发现问题」，读者会当成客体缺陷）。

  | 前缀 | 只用于 | 对应条款 |
  | --- | --- | --- |
  | `OBJ` | **客体**：是否属于专利保护客体、是否落入不授予专利权的情形 | 专利法第 2 条第 2 款、第 25 条 |
  | `NOV` | 新颖性 | 第 22 条第 2 款 |
  | `INV` | 创造性 | 第 22 条第 3 款 |
  | `SUP` | 说明书公开不充分 | 第 26 条第 3 款 |
  | `CLR` | 权利要求不清楚、缺少先行基础、引用关系错误、术语不一致 | 第 26 条第 4 款 |
  | `CLM` | 权项结构问题：独权缺必要技术特征、从属项实质扩宽、单一性 | 实施细则第 23 条、专利法第 31 条 |
  | `EFF` | 技术效果主张与实施例、证据不匹配 | 与 SUP/INV 相关，单独成条时用它 |
  | `FORM` | 形式缺陷：摘要字数、名称字数、图号、著录项、附图标记 | 实施细则及审查指南形式要求 |

  拿不准归哪一类时，按**实际引用的条款**选前缀，不按问题读起来像什么选。
  一个问题同时触及两类（如引用错误又导致保护范围不清）时只编一个号，在正文里写清另一面，
  不重复编号。后续轮次沿用原编号，并把状态明确更新为 `新增`、`维持`、`修改`、`已解决`、`撤回`、`因版本变化失效` 或 `信息不足`。台账里的每个编号本轮都要给出状态；本轮没有写到的编号按 `信息不足` 结转，不得视为已经解决。
- 终审前逐项关闭台账；任何未处置的致命或重要问题必须进入最终结论，不得因轮次变长而静默消失。

## 输入

- 当前唯一母版及明确排除版本；
- 已申请案件的原始申请文件、当前拟审文本和历次审查/答复记录应分开保存。原始申请文件是修改基础证据，不因模拟审查而改写；审查结论只绑定当前拟审文本。
- 当前权利要求和说明书；
- 检索日志、D1、D2 及可能的公知常识证据；
- [权项与证据矩阵](claim-evidence-matrix.md)；
- 实验报告、原始结果和仍待确认项；
- 已知公开事件和优先权信息。
- **同案源码、测试与设计说明（有就必须读）**：母版同目录、其父目录，或用户指定处存在源码、测试、
  设计笔记或 README 时，**必须实际读取并运行可运行的测试**，逐条核验申请稿里的事实性陈述——
  已部署、已上线、用了哪个框架、用了哪种存储、实验数据、性能数字——与代码实际是否一致，
  并在报告里出一张「稿件声称 vs 代码实际」证据核验表（列：稿件原话 / 出处段落 / 代码实际 / 判定
  `一致` `不一致` `代码中不存在` `无法核验`）。**不一致且被写进权利要求或技术效果的，至少 `【重要】`。**
  没有任何可读代码时，在该表位置明确写「无可核验实现」，不得留空，也不得因此把稿件的声称当成已证实。
  （实测踩过：读了源码的宿主靠这一步多抓出三个【重要】——稿件说用了 Redis 和 FastAPI 而代码里根本没有、
  指纹归一化会把两种不同告警并成一条、并发下状态迁移不原子；只读稿件的宿主一条都没看见。）

材料缺失时可以模拟已能评价的部分，但必须标明未覆盖范围，不能把“未检出”写成“没有现有技术”。

在审查开头明确采用哪一种模式：

- `文件内审模式`：没有完成可靠检索，只评价客体、充分公开、支持、清楚、必要技术特征、技术逻辑和一致性；新颖性与创造性只列待检索假设；
- `检索增强模式`：已经实际阅读关键日前公开的 D1、D2 全文，可以作带条件的新颖性与创造性评价。

## 审查分析底线

两份提示词都必须遵守：

1. 新颖性使用单篇文献逐特征判断；需要组合的内容只能评价创造性；
2. 最接近现有技术的选择、区别特征、实际技术问题和技术启示形成完整三步法，避免事后分析；
3. AI、算法或商业规则与技术特征功能上相互支持、相互作用时，应整体考虑，不能只用“去掉计算机后人脑能否执行”判断客体；
4. 缺少实验不自动等于没有技术效果，先判断效果能否由结构和因果机制推出；
5. 对比文件、法条、申请文件段落和实验依据均须可定位；仅凭记忆的内容标为待核验；
6. 已申请案件的修改必须有原始披露基础；申请前可以补充真实、可实现且与主题一致的技术内容；
7. 用户只要求找问题时不改文件；用户允许改稿时才给完整替换文本。
8. 做特征映射之前先过两关：能不能用大白话把整条权利要求讲一遍，能不能用大白话把 D1 实际做的事讲一遍。有一关讲不清就回去读该文献的正文、附图和上下文。映射依据只能是对比文件的说明书正文、权利要求书和附图。检索系统列出的著录摘要、自动生成的中文译文、同族的机器翻译文本，以及检索结果页上的高亮片段，都只用来决定这篇要不要调全文，不能拿来下映射结论——译文和摘要丢掉的往往正是限定条件。
9. 每个特征映射标为 `明文记载`、`毫无疑义确定`、`未记载`、`记载不清`，或者标为并非由本文献公开的 `组合引入`、`主张公知常识`。前四类沿用《专利审查指南》判断“是否公开”的口径：`毫无疑义确定` 指按该文献的记载去实施，本领域技术人员只可能得到这一个结果；存在两种以上实施可能的，一律按 `未记载` 处理。后两类一律不计入新颖性对比，只能转入创造性评价。
10. 新颖性只能拿对比文件中的一项技术方案来比。同一文献里互斥的、或者文献本身没有给出组合关系的两个实施方式，不能拼起来评价新颖性。评价结合时按三步法把话说完整：以最接近的现有技术的哪个具体技术方案为起点，区别技术特征是什么，由该区别特征在本申请中的作用确定实际解决的技术问题，其他证据是否在具体段落里给出了把该区别特征用到起点方案上去解决这个问题的技术启示，两者在技术上是否相互排斥或存在相反教导，以及结合后得到的整体方案能否实现本申请声称的技术效果。
11. 对比文件映射或权利要求解释一旦受到有原文依据的质疑，先做一次准确性复核；映射错误时撤回理由，不用无谓缩窄权项来迁就错误前提。

12. **形式缺陷默认 `【建议】`。** 摘要字数、发明名称字数、图号连续性、著录项、附图标记这类形式问题，
    按平衡审查自己的定义单独不会导致驳回，一律先记 `【建议】`；只有当同一处形式缺陷**同时**造成
    公开不充分或权项不清楚时，才连同那一条实质理由一起升格为 `【重要】`，并写明升格依据的是哪一条实质缺陷。
    （实测踩过：同一个「摘要 429 字 + 缺图 2」，两个宿主一个判【建议】一个判【重要】，
    差别不在证据，在没写死档位。）

13. **清楚性另查一遍术语话题错位。** 前后一致不等于清楚，全文统一地用错词一样对不上号。
    离开本案的标题和技术领域，这个词会不会像另一个领域的行话（写教学系统却用指纹、水位、账本、
    幂等、锚点）？像就记 `CLR`，最小修改是整族换成本领域说法、连附图标签一起换，不是补一句定义
    把它留下来。这不是禁词表，错位的词随案件而变。

不得为显得严格而制造不存在的问题。没有有效攻击的检查项明确写“未发现”或“未找到有效驳回理由”。

## 申请人立场处置

对每项攻击分别判断：

- `反驳`：审查事实、特征映射或技术启示判断有误；
- `澄清`：说明书已有明确内容，但权项或文字需要消除歧义；
- `补证`：现有申请内容已记载效果或机制，需要用原始实验、技术常识或文献说明；
- `修改`：问题成立，应加入有原始依据的技术特征；
- `放弃`：当前主张无法稳健维持，继续争辩价值低。

反驳创造性时，优先围绕区别特征的整体作用、实际技术问题、现有技术没有给出技术启示、两者技术上相互排斥、存在相反教导或效果不可预期，不只重复“文献未公开”。

## 三条处置路线

1. `路线 A：不修改答辩`——写明最强法律和技术理由及失败风险；
2. `路线 B：最小修改`——只加入足以克服主要问题的强区别特征，列明原始说明书依据；
3. `路线 C：保守退守`——使用更具体的关系、状态、组合或参数，说明授权收益和保护范围代价。

不存在可信的不修改路线时明确写“路线 A 不成立”，不得为形式完整硬编理由。每个修改文字必须能在权项—支持矩阵中定位。

## 合并两轮结果

- 两轮都提出、且证据链成立的问题：最高优先级处理；
- 只有平衡审查提出的问题：按法条、证据和影响正常判断，不因红队未提及而忽略；
- 只有红队提出的问题：先验证对比文件、权利要求解释和法律适用；未验证前只记为风险，不自动缩窄权项；
- 两轮结论冲突：回到申请文件原文、对比文件全文和现行审查标准解决，不能用“两个模型投票”决定；
- 依赖未核验现有技术的结论：转成检索任务，不列为已成立缺陷。

## 输出格式

```markdown
### INV-01 模拟审查意见
- 审查版本与 SHA-256：
- 台账状态：新增/维持/修改/已解决/撤回/因版本变化失效/信息不足
- 严重程度：致命/重要/建议
- 验证状态：已证实/待检索验证/信息不足/未发现问题
- 涉及权项：
- 审查标准：
- 对比文件及原文：
- 审查员推理：
- 申请人最佳回应：
- 最小修改文字：
- 原始披露依据：
- 保护范围影响：
- 结论：保留/修改/放弃/待确认
```

最后给出 `通过终审`、`修改后重审` 或 `返回方案阶段`。存在未处置的致命或重要问题时，不标记“通过终审”。修改后只需重跑受影响门槛，但必须再次核对全文和附图一致性。

完整审查另附一张权项覆盖表，至少列出每项权利要求在 `客体 / 新颖性 / 创造性 / 充分公开与支持 / 清楚与引用` 下的状态：`已检查无问题`、`存在问题`、`待检索`、`信息不足` 或 `本轮不适用`。限定范围的单点审查不机械生成全表。空白不代表通过。
